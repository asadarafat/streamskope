# StreamSkope v0.11.2

This documentation patch clarifies advanced workflows and their outcomes, explains technical abbreviations, and moves video masters out of Git. Application behavior and connector packages remain unchanged from v0.11.1.

[Download the approved documentation recordings](https://github.com/asadarafat/streamskope/releases/tag/documentation-media/v1).

## Release highlights

- Documentation videos are pinned GitHub Release assets, keeping MP4 masters out
  of current source and the Pages artifact. Posters, captions and transcripts
  remain available alongside the guides.
- Rendered guides explain the first prose use of technical abbreviations, with
  matching full names in search. Exact controls, commands and archived release
  bodies remain unchanged.
- Installation guidance distinguishes independently released connector packages
  and clarifies per-file versus complete-release checksum verification.

- Under the Skope workflows now explain their purpose, the problem they solve,
  written operating steps and a verifiable result before the optional video.
  Record replay includes a concrete retry example and distinguishes broker
  acceptance, downstream processing and offset resets.

A workbench for inspecting Kafka and NATS streams and their supported operations.

## Signing and installation

These downloads are unsigned. macOS has no Developer ID signature and is not notarized;
Windows is not Authenticode-signed; Linux is not publisher-signed.
Operating-system warnings are expected. Verify the trusted download against SHA256SUMS
before installing. Checksums verify integrity, not publisher identity or malware safety.
Do not disable operating-system security globally.

[Installation and checksum instructions](https://asadarafat.github.io/streamskope/start/installation/)

Install on your Linux host or Linux VM, then open the URL printed by the installer:

```sh
curl -fsSL https://github.com/asadarafat/streamskope/releases/download/v0.11.2/install-browser-workbench.sh | sudo -E bash
```

The installer verifies the matching release metadata, pulls the public version/digest-pinned
GHCR image, and preserves private vault data on repeat runs. No source build is required.
Manual and offline delivery remain available through the matching topology and image archives.
No Apple Developer ID certificate is needed.
The browser stores credentials in an encrypted vault that you unlock with your
passphrase; protect that passphrase and the private data directory.
