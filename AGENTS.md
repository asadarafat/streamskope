# StreamSkope development

- Keep each PR to one reviewable outcome. State that outcome and executed checks in the PR body; use the repository PR template.
- Run focused tests while editing. Local `npm run check` runs shared static/unit/integration and documentation checks plus a 60-second soak and configured live EDA/NSP tests. GitHub runs `npm run check -- --ci` on PRs and main for qualification only. Maintainers start the separate Release workflow from main, select desktop or a plugin and supply its SemVer. Release CI qualifies the selected source before stamping a disposable build checkout; main retains `0.0.0-dev`. Desktop releases build Linux/macOS/Windows native packages and the complete unsigned EDA application; plugin releases package and draft only the selected plugin. Tags are output, not release triggers. Pages deploys only after desktop release publication, qualifies that exact tagged source with matching version/downloads and the publication event's release notes, then verifies the public revision. PRs/main qualify development docs without deployment. Signed EDA publication remains manual. Record executed checks; do not report an unexecuted or skipped check as passed.
- Add an independent regression test when observable behavior changes. For behavior-neutral edits, use a relevant validator or inspection instead of a fabricated failing test.
- Preserve the renderer → typed host contract → backend facade → application behavior → Kafka adapter boundary. Renderer code must not access Node, Electron, files, secrets, or Kafka libraries directly.
- OpenSpec is private and Git-ignored here. Use the installed OpenSpec tooling only for durable contracts or consequential cross-layer changes; keep release operations and repository cleanup in separate changes. Public PRs must carry their own concise acceptance evidence.
- Do not infer live Kafka, EDA, package-signing, registry, or publication success from unit or workflow-text tests. Record real-system evidence for those claims.
