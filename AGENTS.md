# StreamSkope development

- Keep each PR to one reviewable outcome. State that outcome and executed checks in the PR body; use the repository PR template.
- Run focused tests while editing. Local `npm run check` runs shared static/unit/integration and documentation checks plus a 60-second soak and configured live EDA/NSP tests. GitHub runs `npm run check -- --ci` on PRs for qualification only; main pushes do not repeat it. Require the **CI** check and an up-to-date branch before merging, without bypassing the PR requirement. Maintainers start the separate Release workflow from main, select desktop or a plugin and supply its SemVer. Release CI calls the same qualification workflow for the selected source before stamping a disposable build checkout; main retains `0.0.0-dev`. Desktop releases build Linux/macOS/Windows native packages, native Linux AMD64/ARM64 browser archives with vault/restart checks, a public multi-platform GHCR image verified by anonymous pulls, and the complete unsigned EDA application. Browser delivery adds six public files: two Docker save archives, an image manifest, a version/digest-pinned online topology, a local-image offline topology and a stamped installer. Native AMD64/ARM64 installer jobs qualify public-image installation, encrypted vault persistence and resume after registry promotion and before drafting. Root `streamskope.clab.yml` remains offline source deployment. Plugin releases package and draft only the selected plugin. Tags are output, not release triggers. Pages deploys only the highest published stable desktop SemVer, verifies its immutable tag and commit before build and deployment, qualifies that exact tagged source with matching version/downloads and the publication event's release notes, then verifies the public revision. PRs qualify development docs without deployment. Signed EDA publication remains manual. Record executed checks; do not report an unexecuted or skipped check as passed.
- Add an independent regression test when observable behavior changes. For behavior-neutral edits, use a relevant validator or inspection instead of a fabricated failing test.
- Preserve each messaging provider's renderer → typed host contract → backend facade → application behavior → protocol adapter boundary. Kafka and NATS are built-in siblings; EDA/NSP remain Kafka connection plugins. Renderer code must not access Node, Electron, files, persisted secrets, Kafka libraries or the NATS SDK directly. Product composition registers typed lazy workspaces; connection handoffs confirm stream stop before disconnect through the original host, and preserves already-admitted receipts and cleanup events.
- OpenSpec is private and Git-ignored here. Use the installed OpenSpec tooling only for durable contracts or consequential cross-layer changes; keep release operations and repository cleanup in separate changes. Public PRs must carry their own concise acceptance evidence.
- Do not infer live Kafka, EDA, package-signing, registry, or publication success from unit or workflow-text tests. Record real-system evidence for those claims.
