# StreamSkope development

- Keep each PR to one reviewable outcome. Use a Conventional Commit title and the repository PR template; state the behavior, executed checks and material unverified scope.
- Run focused checks while editing and `npm run check` for local acceptance. The only dependency exception is a Dependabot PR accepted by the [routine tooling policy](maintainers/dependencies.md#routine-tooling-acceptance): its successful GitHub qualification replaces duplicate local acceptance. GitHub qualifies every PR through shared, documentation and runtime lanes; require all three and the final **CI** check, plus an up-to-date branch, before normal protected merge. Do not bypass the PR requirement. Main pushes do not repeat CI. The [qualification guide](maintainers/qualification.md) defines scope, live effects and evidence limits.
- Preserve complete source-bound qualification bundles, including explicit skips. Do not infer live-system, native package, signing, registry or publication success from unit or workflow-text tests. Never relabel a receipt; use the validated draft-only attachment procedure in the qualification guide.
- Add an independent regression when observable behavior changes. For behavior-neutral edits, use the relevant validator or inspection instead of a fabricated failing test.
- Keep exactly five root npm entry points: `dev`, `build`, `check`, `package` and `docs`. Use their existing arguments and task-specific modules. Setup and owned fixture cleanup are in [development](maintainers/development.md).
- Preserve renderer → typed host contract → facade → application → protocol adapter boundaries. Kafka and NATS are built-in siblings; EDA/NSP are Kafka connection plugins. Renderer code must not access Node, Electron, files, persisted secrets or messaging SDKs. Follow the [architecture guide](maintainers/architecture.md) and executable import/ownership rules.
- Keep authority with the owner across cancellation, reconnect and cleanup. Reject new work after revocation, preserve admitted receipts and uncertain outcomes, and confirm stream stop through the original host before disconnect. Watchdog diagnostics cannot release authority or prove remote cleanup. Do not delete recovery state to bypass an unresolved operation.
- Maintainers assign versions through manual release CI on main; source stays `0.0.0-dev`. Tags are outputs, not release triggers. Qualification and publication are separate. Pages follows the highest published stable desktop SemVer, pins its immutable source and matching assets, and never publishes newer main as an older release. Release records synchronize through an ordinary protected PR. See [releases](maintainers/releases.md) and [documentation](maintainers/documentation.md).
- Browser storage changes must preserve vault/lease ownership, compatibility preflight, complete verified backups and durable recovery. Require native install/upgrade/rollback evidence for the affected architecture; local staged evidence cannot stand in for public delivery. Follow the browser compatibility section of the qualification guide.
- Dependency changes must retain mitigation ownership and retirement evidence. Follow [dependency maintenance](maintainers/dependencies.md); qualify the dependency graph that changed.
- OpenSpec is private and Git-ignored here. Use the installed OpenSpec tooling for durable contracts or consequential cross-layer changes; keep release operations and repository cleanup separate. Public PRs must carry their own concise acceptance evidence. Keep credentials, generated artifacts and private planning out of commits.
